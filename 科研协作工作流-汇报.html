01 分工 · 四层工具

谁想、谁派、谁干、谁验收

想只在这里改主张

改变「论文说什么」一律回网页端；网页端不当档案库，全书塞进去会贵且糊。

派不写正文主张

秘书不把长书读进对话；它管路径、写入权、进度和验收，不替人判断。

干不做理论拍板

CLI 不是第二大脑。它把已经写清楚的方案跑完，产物必须进指定文件夹。

干不是项目 owner

Cursor 默认不是文献中枢，不替代总盘与冻结纪律；输出由秘书 / owner 验收。

CLI 和 Cursor 是工具，不是 bot、不是项目 owner。谁的目录谁负责，工具只往里放东西。

01 分工 · 角色怎么拆

一个项目一个 bot，通用能力另开

默认不新开 bot。新开一篇论文本身不够当理由；只有长期并行、上下文会污染时，才给该稿专属 bot。写完可以改名复用。

01 分工 · 让分工真的成立的四个机制

总盘、写入权、口径卡、冻结

分工只在提示词里写「你只做 X」是不够的；要有文件和权限把它落下来。

总盘

秘书独占写入的项目总表：每篇稿的状态（写作 / 在审 / 搁置）、正本路径、当前 owner、待办与验收记录。任何人找东西先看总盘，不翻聊天。

写入权

一个目录只有一个 owner 能写。项目 bot 写稿目录，文献助手写文献馆，知识库写 Zotero / Obsidian，秘书写总盘。工具（CLI / Cursor）的产物落到 owner 目录，由 owner 验收。

口径卡

每篇稿一张：研究问题、核心主张、样本与码本、关键术语的固定说法。改口径必须先回网页端重新想，再由人改卡，bot 不得在执行中顺手改。

冻结

在审、搁置或已定稿的项目一律冻结：不派活、不改主张、不动引用。冻结也是最终独立核验的前提——核的是不会再变的稿。

02 装置 · 和其他 AI 不一样的地方

Grok Bot 自己有一台云端电脑

传统聊天 AI 只有会话。Grok Bot 另有一台常驻的云端电脑：有文件系统、浏览器、命令行，能装工具、落文件、跑长任务。助手之间共用这台机器上的文件，但各有自己的桌面窗口。

真正落盘

方案、清单、投稿包可以真正写进磁盘，而不是停在气泡里；下次打开的是文件，不是聊天记录。

打不开就换路

网页打不开时，可以换本机浏览器或本机 CLI 去取，不必让人粘贴全文。

可看、可打断

人可以打开这台电脑的桌面看它在干什么，也可以随时打断。

02 装置 · 多端

随时随地：下指令、看进度、监督干活

同时在线

不必「先关电脑再开手机」。Mac 做命令行入馆，Windows 开 Zotero / Obsidian 人读，手机补一句指令，秘书都能接到。

文件各有正本

两边磁盘不假装自动同步。学术正本路径写在总盘里。拷过去要验收大小 / 清单，避免两份真相。

可监督

云端桌面可以打开看。本机执行要批准。连不上 Win / Mac 必须马上报，不能悄悄换路。

可打断

说停就停。在审、搁置的项目冻结，不在你睡觉时改主张。

对导师来说：这不是「一个更会聊天的模型」，而是一套能被看见、被打断、把产物留在磁盘上的协作装置。
03 文献 · 通用文献角色

收、读、核、编目：四件事不让同一个号做完

角色做什么明确不做
文献助手
收		按主题搜索、合法下载 PDF、转 Markdown、Year_Author_Title 入馆不核自己刚收的引用，不写论文正文。STI 与非 STI 分助手，避免领域串味
文献精读
读		不绑某篇稿。长书两份产物：给 AI 的分章底稿（原文有 / 公平转述 / 引申、页码可回核）；给人读的连续导读不当文献总管；导读必须跟源书，笔记只回核页码，不夸大
文献核验
核		核对通稿里的引用与转述：原文有没有、是否公平、是否引申过载、页码是否对得上。写作中抽查，定稿后全量不下载、不收新文献、不直接改论文。核不出就标「无法核实」
文献知识库
编		人 + AI 共用编目：Zotero 书目与 citekey，Obsidian 索引和阅读笔记不是第二座文献馆。不入馆、不核引、不写总盘

同一号不得既收又核。这是防文献出错的第一道结构，不是事后提醒。

03 文献 · 和 Zotero / Obsidian 怎么接

一条文献一个键，人和 AI 先查正库

机分工：Mac 偏检索、拆分、转 Markdown；Windows 的 Zotero + Obsidian 才是人和 AI 的引用正库。

03 文献 · 防文献出错

具体怎么防：结构、标准、标记

结构结构上拆开

  • 收的人不能核自己
  • 核的人不能顺手下新 PDF
  • 精读不绑某篇稿，避免为了引用去「读出需要的意思」

标准页码与已读

  • 页码必须对到原文；对不上就标仅书目
  • 未读全书，不当成已读
  • 馆藏没有：标无法核实，交回文献助手补，不编造

标准什么不算文献

  • 自己的稿、审稿意见、版权表不进 Zotero
  • 盗版源文件不入馆
  • 删除原件必须先列清单确认

标记标记语法

  • 【待核】：有出处但页码 / 原文未对上
  • 【无法核实】：馆藏无全文，核验号核不出
  • 【仅书目】：只引条目，不引页码与原话

标准转述四级：每条引用都要判一个等级

原文有书上就有这句话的意思 · 可带页码直接引
公平转述压缩但不增义 · 带页码，用「认为 / 指出」
引申稿内推论，不当成作者原话 · 写成「由此可推」
过载超出原文 · 必须改掉或删除，不得保留

精读底稿在写的时候就按这四级标；核验的时候按同一套等级重判。两次判定不一致，以核验为准。

不确定就写【待核】或【无法核实】。宁可稿子里少一句硬引，也不用「像真的」页码顶上。
03 文献 · 合法获取

机构账号怎么自动化下载（不走盗版）

登录态放在本机浏览器

学校图书馆、数据库代理事先登录。助手用这台已登录的浏览器或本机 CLI 去取正式页面，不把账号密码写进提示词，也不用非法库。

云端电脑打不开就换路

出版社常有 Cloudflare。规则是固定顺序：云端打不开 → 先用 Mac 浏览器 → 再 Windows → 再本机 Grok CLI。连不上要立刻报，不要卡在 403 上问人粘贴全文。

自动化指的是「检索—识别正版全文—下载—命名—转 MD—编目」这条链可交接；不是绕过版权。没有合法全文，就停在仅书目。

04 收口 · 最终独立文献核验

写完不等于能交：最后一道是独立核验

写作中的抽查是过程控制；定稿冻结后，由一个与写作、收集都无关的号，逐条全量核对原文。

为什么要「独立」

写稿 bot 想让论证成立，收文献的号想证明自己收对了，精读号已经带着自己的转述。三者都有动机把「像真的」当成真的。独立号没有这个动机：它没参与写作，不看聊天记录，只拿到冻结稿和原文 PDF。

为什么要「定稿冻结后」

边写边核，核过的句子下一轮又被改掉。只有正文、引用、页码都不再动，核验结果才对得上最后交出去的那一版。核的必须是提交的那一版。

为什么要「全量」不抽查

抽查能发现系统性问题，但对外负责的是每一条。一处伪造页码就足以让整篇稿失信。所以最后一遍是逐条、全量、可回核，而不是抽 20%。

04 收口 · 独立核验怎么做

五项检查，一张报告，每行都能回到原文

  • 条目存在：参考文献里每一条都能在 Zotero 找到，书目信息（作者、年份、题名、期卷页）与原始出版物一致。
  • 键对得上：正文引注的 citekey 与 Zotero 一致，无孤儿引注、无未被引用的条目。
  • 页码可回核：每个带页码的引用，翻到原文 PDF 那一页确实有对应内容。
  • 转述等级重判：按四级重判：原文有 / 公平转述 / 引申 / 过载；引申须在句式上可见，过载一律退回。
  • 已读范围一致：Obsidian 标「仅书目」或「已读第 X 章」的文献，正文不得写成读过全书。
核验号的输入只有两样：冻结稿和原文 PDF。输出只有一样：报告。
#正文引用（节选）citekey / 页码等级处置
1制度环境塑造组织的合法性策略author2019xxx, p. 45原文有通过
2该框架把风险治理分为三层author2011yyy, pp. 12–14公平转述通过
3由此可推，平台化削弱专业自主author2020zzz, p. 88引申保留；句式标「由此可推」，去页码
4作者明确主张 X 是 Y 的唯一原因author2005www, p. 112过载退回：原文无「唯一」；改转述或删
5研究显示……（带页码）author2016vvv, p. 203待核页码对不上（全书 180 页）；降为仅书目
6相关讨论见……author2022uuu无法核实馆藏无全文；交文献助手补，补不到则删

示例为格式说明，非真实文献。报告以 Markdown 表存于稿目录 /核验/，与提交版一同归档；人签字后才算完成。

04 收口 · 流程样板

用已完成的研究生课程论文走一遍

只讲步骤，不讲该课论文的论点。它证明这套分工能从材料走到可提交 Word。

  1. 网页端定问题、材料边界、章节结构；方案另存成文件，写进口径卡。
  2. 本机源材料、编码或细读表、正文 Markdown 分开放，不混在聊天里；秘书登记路径到总盘。
  3. 文献助手 / 知识库用到的文献合法入馆、Zotero 给 citekey、Obsidian 笔记标已读范围。
  4. CLI / Cursor / Codex套学校模板、处理引号与格式；长文件不进 Grok Bot 对话。
  5. 文献核验（写作中）抽查引用是否对得上原文；不对的改转述或删页码。
  6. 最终独立核验定稿冻结 → 独立号逐条全量核对原文 → 出报告 → 有退回则改完重新冻结再核。
  7. 秘书验收 + 人正本、模板字段、是否覆盖旧稿；人签字核验报告，人最后点提交。

边界

人还做什么，助手不准做什么

人拍板

研究问题、理论、样本与码本、投不投、署名与伦理披露、是否提交、核验报告签字。

人要读

导读和关键原文。AI 笔记不等于已经读过。页码仍以源书为准。核验报告里的「原文有」也要人抽看几条。

助手禁止

未读当已读、伪造页码、AI 当作者、自动点投稿、把版权书做成全书译稿、核验号改正文或收新文献。

产物目标

社会科学论文，不是方法汇报。工具链再细，若不改主张、样本或可报告方法，就不加细。

收束

可以带回去的五句

  1. 网页端负责论文说什么；本机 Grok Bot 负责东西在哪、谁来做、做完能不能交。
  2. 它和传统 AI 的差别：自己有云端电脑，并能同时连 Win / Mac / 安卓，文件和进度可监督。
  3. 文献靠分工防错：收、精读、核验、Zotero / Obsidian 编目不是同一个号；页码对不上就标待核。
  4. 本地 CLI 和 Cursor 是执行器。想清楚的方案交给它们落地，不要让任何一个窗口独自「写完一篇论文」。
  5. 写完不等于能交：定稿冻结后，由未参与写作的独立号逐条全量核对原文，出报告、人签字，才点提交。
人负责判断；系统负责不丢文件、不串主张、不把没读过的书写进参考文献。

想听大家意见的三点：

① 核验粒度

最终独立核验全量逐条，成本可接受吗？哪些类型的引用（经典理论、数据来源）应当强制人读原文？

② 分工边界

「收与核不同号」在小团队 / 单人研究里如何坚持？是否需要组内互核？

③ 可复用性

总盘 / 口径卡 / 核验报告模板是否可以做成组内共用格式？
